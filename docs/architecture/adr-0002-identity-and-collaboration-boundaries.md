# ADR-0002: Identity, affiliation, case, and resource boundaries

- **Status:** Accepted for Phase B1 review
- **Date:** 2026-10-30
- **Tickets:** RES-003, RES-004, RES-010, RES-011, RES-040

## Decision

Identity persistence is isolated in PostgreSQL schema `auth` and matches the four
Better Auth 1.7.14 core models. Resurgo-owned collaboration data is isolated in
schema `resurgo`.

Organizations and cases are deliberately different security boundaries:

1. An organization records professional affiliation and administrative role.
2. A case records a collaboration context between individually identified users.
3. A professional case membership must reference an organization membership for
   the same user.
4. Organization membership does not create or imply case membership.
5. Neither organization nor case membership implies access to a classified
   resource.
6. A resource grant names a specific case membership, resource, classification,
   and operation.
7. A cross-professional grant names a consent whose recipient, classification,
   operation, and case must match through a composite foreign key.

## Database enforcement

- Opaque UUID primary keys are generated by PostgreSQL.
- Composite foreign keys reject cross-case membership, resource, consent, and
  grant references.
- The professional affiliation foreign key includes the user ID, preventing one
  user from presenting another user's organization membership.
- A professional can enter a case only through an active membership in an
  organization marked `verified` for the pilot. Candidate organizations do not
  qualify.
- Cases reference an extensible jurisdiction registry, and a trigger rejects
  disabled entries. Only Fulton and DeKalb Superior Courts are enabled for v0.1.
- A deferred constraint trigger requires every case to commit with exactly one
  active owner membership. Ownership transfer must preserve that invariant in a
  single transaction.
- Audit events are append-only at the database boundary; update and delete raise
  SQLSTATE `55000`.

## Authorization boundary

Phase B1 includes narrow server-domain decisions for effective case and resource
access. They re-evaluate case and organization membership lifecycle, pilot
organization status, requested operation, consent/grant lifecycle, and time
bounds for each decision. Paused and closed cases fail closed. The database and
policy layer both restrict `case_owner` grant basis to the case's owner
membership. Revoked or expired grants remain historical evidence and never
authorize access. RES-010 must still bind these decisions to an authenticated
principal and every request route; a row identifier supplied by a client is
never proof of access.

Audit hashes are shape-checked and unique, but Phase B1 does not yet compute or
verify a tamper-evident chain. Database roles are also not yet split between
runtime, migration, and audit-reader identities. Neither limitation is an ASVS
verification claim.

## Consequences

This model can support multiple professionals from different organizations in a
single case without making any organization a tenant-wide case owner. It also
preserves a stable security envelope for later document, scheduling, contract
analysis, and court adapters without granting those adapters implicit access.

The v0.1 configuration is Atlanta-specific without encoding nationwide court
behavior: `GA-FULTON-SUPERIOR` and `GA-DEKALB-SUPERIOR` are the only enabled
jurisdictions. Adding another jurisdiction requires a reviewed configuration
change rather than a new schema.
