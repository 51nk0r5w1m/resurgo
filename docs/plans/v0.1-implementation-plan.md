# v0.1 dependency-ordered implementation plan

**Status:** Architecture direction approved. Checkpoint A foundation work is
implemented; Checkpoint B remains behind the requested review gate.

## First eight tickets

1. **RES-001 — Bootstrap monorepo and CI.** Create the pnpm workspace, strict
   TypeScript configuration, Next.js shell, lint/format/unit/Playwright commands,
   pinned lockfile and actions, secret/SCA/SAST scanning, SBOM, and build cache.
2. **RES-004 — Threat model and security baseline.** Review this draft, complete
   the ASVS 5.0.0 L2 applicability matrix, approve classifications, policy
   vocabulary, upload limits, and production security assumptions.
3. **RES-002 — Local self-hosted environment.** Pin PostgreSQL, a reviewed
   open-source S3-compatible store, ClamAV, and a local mail catcher in Compose;
   bind administrative ports locally, use health checks and separate
   least-privilege credentials, and document clean start/stop/reset commands.
4. **RES-003 — Domain schema and migrations.** Implement Better Auth-compatible
   identity tables plus cases, memberships, versioned discovery, rules, roadmap,
   authorization, document metadata, jobs, and audit foundations with composite
   case foreign keys. Validate up/down/clean migrations in CI.
5. **RES-006 — Better Auth registration and sessions.** Implement verified email,
   registration, sign-in/out, recovery, protected routes, rotation/revocation,
   generic failures, CSRF/trusted origins, and rate limiting. Do not mark complete
   after login alone.
6. **RES-010 — Central case policy engine.** Define typed actions and attributes,
   default deny, server-only enforcement, case-scoped repositories, and a complete
   two-user BOLA/IDOR test matrix.
7. **RES-011 — Consent and scoped disclosure.** Model recipient, action, purpose,
   classification, expiry, revocation, immutable terms, and policy overrides.
   v0.1 may expose owner grants only, but document access must use this model.
8. **RES-012 — Separate legal and financial domains.** Enforce compartment and
   field projection rules; add tests proving status-only handoffs cannot contain
   privileged, credit, health, or raw document payloads.

`RES-040` (immutable audit events) follows immediately and is a prerequisite for
document release. `RES-005` can proceed alongside the security foundation but
must not expose nonfunctional controls from the later wireframes.

## Increment quality gates

Every ticket has two independently reported results:

- **Functional acceptance:** user-visible behavior and its unit/integration/E2E
  evidence.
- **Security acceptance:** negative authorization, input-abuse, isolation,
  redaction, or configuration evidence mapped to version-qualified ASVS controls.

The standard command contract should become:

```text
pnpm install --frozen-lockfile
pnpm infra:up
pnpm db:migrate
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm test:integration
pnpm test:e2e
pnpm db:validate
pnpm security:secrets
pnpm security:dependencies
pnpm build
```

No ticket is complete when a required negative authorization test fails, a
migration cannot initialize a clean database, or its separate security acceptance
criteria lack evidence.
